# internal/db

## Overview

The Go side of the database: `Open` builds the pgx pool and pings it, `queries/` is the typed code sqlc generates from `db/queries/*.sql`, and `dbtest/` gives each test its own migrated scratch database. The SQL, the migrations, and the roles live in `db/`; read [db/AGENTS.md](../../db/AGENTS.md) first for those rules and gotchas. This file covers only what is local to the Go package.

## Key files

| File | Owns |
|---|---|
| `db.go` | `Open(ctx, url)`: parses the URL, pings with a 5 second timeout, and closes the pool on failure so a binary stops at startup |
| `queries/` | generated by sqlc (`Code generated by sqlc. DO NOT EDIT.`): one `*.sql.go` per file in `db/queries/`, plus `models.go` and `db.go` |
| `dbtest/dbtest.go` | `dbtest.New(t)`: a scratch database per test, cloned from a migrated template, with a pool per role (`Owner`, `Agent`, `ToolServer`, `Eval`, `Grafana`) |
| `queries_test.go` | behavior of the shared queries: thread upsert, gapless `seq` under concurrency, status moves only from open, purge, Slack event dedup, usage sums, eval runs |
| `grants_test.go` | which role reaches which table, column grants, and that no role can change an audit row |
| `ops_test.go`, `dashboard_test.go` | spec 0016: outcome pairing, failure rows, the one row kill switch, what `noord_grafana` can see and its limits, the `ops` column name rule, and every dashboard panel query run as `noord_grafana` |
| `db_test.go` | `Open` rejects a bad URL, fails fast when unreachable, and pings a live database |

## Commands

```bash
make gen                                          # regenerate queries/ after editing db/queries/*.sql; it must leave no diff
TEST_DATABASE_URL=<superuser url> go test -race ./internal/db/...   # DB tests skip without it
```

## Conventions

- Never edit `queries/`. Change `db/queries/*.sql` (or a migration) and run `make gen`; CI and the pre push hook fail on a stale result.
- Pick the pool for the role you are testing. A test that uses `d.Owner` for something an app role must do proves nothing about grants.
- A new table needs its row in `grants_test.go` in the same change as its migration.
- Keep a dashboard panel query in `dashboard_test.go` and run it as `noord_grafana`, so a panel that reads outside `ops` fails the test.

## Gotchas

- `noord_grafana` may hold only 5 connections for the whole server. `dbtest` gives it a lazy pool of one connection, so never open it eagerly in a test helper.
- `CREATE DATABASE ... TEMPLATE` does not copy privileges. `dbtest` repeats the `REVOKE TEMPORARY` from migration 00008 on every scratch database, so a new database level grant or revoke must be repeated there too.
- Setup runs under one advisory lock, because roles are cluster wide and a template must be idle to clone. Do not add setup work outside that lock.
