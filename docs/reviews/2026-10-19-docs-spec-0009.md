## Minor
### 🟡 The department term has no length floor, so short departments mangle the text IT needs, `internal/agent/redact.go:63`
**Problem**: The name rule removes the full department with no minimum length. Name parts need 3 letters, but the department does not. Noord's seed has departments `IT` and `HR`. For a requester in IT, every whole word `IT` in the model's summary becomes `[department]`. Because the boundary test treats `-` as a non letter, `SG-IT-Admins` becomes `SG-[department]-Admins`. The same applies to a name part like `van` from `Peter van Dijk`, which is replaced in any sentence.
**Why it matters**: The privileged request is exactly where an IT person says "add me to SG-IT-Admins". The IT post would hide the group name IT must act on, and "only IT can grant that" would read "only [department] can grant that". This follows the spec text literally, so the fix may be a spec amendment, not just code.
**Suggested fix**: Decide whether to add a minimum length for the department term, or skip redaction when the department is a standalone word that also appears in a known group name. Add a unit test with department `IT` and the text `SG-IT-Admins`. If you keep the behaviour, note it in the spec's Consequences.

### 🟡 Failed history reads are swallowed with no log line, `internal/agent/failure.go:26`
**Problem**: `calls, _ := ...listCalls(...)` ignores the error in `failurePath` (failure.go:26), `modelEscalated` (loop.go:252), and `escalateInterrupted` (sweep.go:73). Only `backstop` logs `agent_backstop_failed` when the same read fails. The comments say what happens, but nothing is logged.
**Why it matters**: When the store is down, the failure path escalates as `assistant_failure` even if a blocked attempt exists, and the IT post shows an empty `Ran:` line. The tool server still tags the ticket as privileged from the audit log, so the damage is small. But the repo rule is to never silently swallow errors, and an operator cannot tell why a ticket note says `assistant_failure` for a privileged case.
**Suggested fix**: Log one `agent_history_read_failed` warning with the fixed cause token in those three places (static message, snake_case keys). No behaviour change needed.

### 🟡 `ZAMMAD_PUBLIC_URL` is trimmed in the wrong place and accepts credentials, `internal/config/config.go:376`
**Problem**: Spec AC-13 says `LoadToolServer` trims a trailing `/`. The config only validates. The trim happens in `tools.NewHelpdesk` (`internal/tools/helpdesk.go:35`) and removes a single slash. Also `isPublicURL` accepts `http://user:pass@host`, and that value would be posted into the IT channel inside every ticket link.
**Why it matters**: Small spec drift, plus a way to leak a credential into Slack history by a config slip. Low likelihood.
**Suggested fix**: Trim in `LoadToolServer` as the spec says (and assert it in `TestLoadToolServerEscalationSettings`), and refuse a URL with userinfo.

## Nits
- ⚪ `internal/tools/escalate.go:63`, `escalate` is about 60 lines, over the 50 line guide. Splitting the tag and create step into its own helper would bring it under.
- ⚪ `internal/agent/loop.go:250`, `t.reason` and the `agent_escalated` log take the `reason` from the tool result without checking it is one of the three model tokens. If it were missing, `itHeadlines[reason]` returns an empty string and the IT post would start with a blank line. A small guard (fall back to the privileged or `other_person` headline, or skip the post and log) would make the fixed token promise hold in code.
- ⚪ `docs/specs/0009-refusal-escalation/verify.md:87`, the first live run of phrasing 1 is recorded as a finding (the IT post carried the name and department, which the spec forbids), yet the table marks it "yes, except..." and the total says 21 of 21. Run 2 and later runs did use the fixed build, so the claim is probably fine, but say plainly that run 1 failed the original criterion and was covered by a rerun.
- ⚪ `docs/specs/0009-refusal-escalation/index.md:4`, status still reads "In Progress" and the Follow up boxes are unticked. This is /sync's job, noting it so it is not forgotten.
- ⚪ `internal/agent/redact.go:78`, `termAt` builds two strings per term per position (`string(text[i:end])`). At 10000 runes and a handful of terms this is cheap, so only worth touching if you already edit the file.

## Strengths
- The trust boundary is tight. The initiator key is checked three times: optional but exactly `code` in `internal/mcpserver/meta.go`, set only on a copy of the requester in `escalateByCode` (the stored `t.requester` is never mutated), and enforced for the code only reasons in `checkEscalate`. A model sending `assistant_failure` gets `invalid arguments` with no initiator on the wire.
- Every audit read in `escalate` comes before any Zammad call, ownership and closed state are checked before any tag is written, and `title` and `summary` stay out of the audit row, logs, and spans. The hygiene tests cover all three.
- The IT post is built only by code from stored values. Model text goes through collapse, name redaction, cut, then escape, and sits last, so it cannot fake a `Ran:` or `Ticket:` line or fire a mention or link. The ordering is pinned by `TestModelSummaryOrder` and `TestITPostEscapesTheSummary`.
- The post goes out right after the result commits, so a later model failure cannot swallow it, and the backstop, failure path, and sweep all share one escalation path with the same tags and post.
- The test fake now matches the real wire format (the `<code>: ` prefix), and journal 0034 records why. That kind of fake drift is easy to miss.

## Test coverage
Coverage is strong. The tool side has table style tests for creating, tagging, finding the thread ticket, once per thread, wrong owner, closed and merged tickets, audit read failure with no Zammad call, partial tag failure, attempt counting with a window edge, window hour truncation, the close guard and its edges, and the kill switch not applying. The agent side covers the model path, the backstop (success, failure, already escalated, unreadable history, earlier turn), the failure path reasons, the sweep with a privileged history, the IT post format and escaping, the name rule, not matched posts, post failure logging, and log and span hygiene. Config, `_meta` initiator, `Reply` with an empty thread, and `AddTag` are covered too. Gaps are small: no test for a department like `IT` meeting `SG-IT-Admins` (see the first minor finding), no test for an unknown or missing `reason` in an escalate result, and the Postgres backed audit tests did not run in this review (they need `TEST_DATABASE_URL`; `verify.md` records them passing).
